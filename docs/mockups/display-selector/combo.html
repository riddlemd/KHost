01 Live on the button, the rest under the chevron Recommended

The button answers "where is this going?" at a glance, which is what it already does. The chevron answers "somewhere else", which is the part missing today.

The live display is deliberately absent from the menu. A split button's primary is the current choice, so listing it again would invite a press that does nothing. Search sits below a rule because it is a different kind of act — it changes the list rather than choosing from it.

02 One display, no chevron

SplitButton already hides its toggle when the menu renders no items, and gives the primary back the corner and border it gave up. A venue with only the local screen sees exactly the button that is there today.

Worth saying plainly: this costs nothing to build. The behaviour is in the component, asked of the rendered markup rather than passed as a parameter, so an empty menu is enough.

03 The two other states

Nothing live keeps the primary as the verb — pressing it opens the display a host used last, which is the one-press path for the ordinary night. The chevron is still there because receivers were found, so there is a real choice to make.

The dot carries the state in both: grey for off, green for live. It is the same signal the header button uses now, so nothing has to be relearned.

04 Choosing one mid-song asks first

Only while a song is playing. The new display gets its own stream and starts from where the song is, which the room hears as a gap — so it is worth a press to confirm.

Between songs it should switch without asking. A prompt that appears every time teaches a host to dismiss it without reading, which is worse than not having one.

05 A receiver mid-connect

A Cast connect takes seconds and can fail — an address mDNS advertised may not be reachable. The row stays in place, disabled, saying what it is doing.

Removing it and putting it back would read as the list flickering, and a host who pressed it would not know whether the press landed.
